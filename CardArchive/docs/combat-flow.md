# 전투 흐름 (공격 순서 / 타겟 지정)

최종 갱신: 2026-08-03

한 번의 전투 페이즈에서 **어느 유닛이 어떤 순서로**, **무엇을 대상으로** 공격하는지를
예시 필드로 정리한 문서다.
효과 발동 순서와 사망 처리 타이밍은 [`effect-resolution-flow.md`](effect-resolution-flow.md)에 있고,
회귀 검증은 [`../Tools/ResolveQueueTests`](../Tools/ResolveQueueTests)의 전투 12종에 있다.

## 1. 보드 구조

좌표는 `(x, y, p)`다.

| | 의미 | 범위 |
|---|---|---|
| `x` | 행 안에서의 위치 | 1 ~ 6 |
| `y` | **행** (아군 진영 → 중립 → 적 진영) | 1 ~ 5 |
| `p` | 소속 진영 | `y<3` → 0 / `y==3` → 2(중립) / `y>3` → 1 |

행마다 폭이 다르고 시작 x가 달라서 **육각형**이 된다 (`Slot.GetAll`):

| 행 | x 범위 | 칸 수 | 진영 |
|---|---|---|---|
| y=5 | 3~6 | 4 | 적 |
| y=4 | 2~6 | 5 | 적 |
| y=3 | 1~6 | 6 | 중립 |
| y=2 | 1~5 | 5 | 아군 |
| y=1 | 1~4 | 4 | 아군 |

### ⚠️ 세로축 ≠ x 좌표

화면상 **세로축(열)은 `2x − y`가 같은 칸들**이다. 육각형이라 행마다 반 칸씩 어긋나기 때문에,
같은 세로축은 `x`가 아니라 대각선으로 이어진다.

```
              (3,5)  (4,5)  (5,5)  (6,5)          ← y=5  적 진영
         (2,4)  (3,4)  (4,4)  (5,4)  (6,4)        ← y=4  적 진영
    (1,3)  (2,3)  (3,3)  (4,3)  (5,3)  (6,3)      ← y=3  중립
         (1,2)  (2,2)  (3,2)  (4,2)  (5,2)        ← y=2  아군 진영
              (1,1)  (2,1)  (3,1)  (4,1)          ← y=1  아군 진영
```

세로로 내려가는 줄이 세로축이다. 예를 들어 3번 세로축은 `(3,5) → (2,3) → (1,1)`이고,
x가 3, 2, 1로 **줄어든다**.

### 인접 6방향

`GetNeighborSlot` — `(-1,0) (0,+1) (+1,+1) (+1,0) (0,-1) (-1,-1)`.
사거리는 이 인접 관계로 BFS를 돌려 구한다 (`GetRangeSlot`).

## 2. 공격 순서

`Slot.GetAttackOrder(0)`이 만드는 순서를 규칙으로 환원하면:

> **세로축을 왼쪽부터 훑고, 같은 세로축 안에서는 위(적 진영)에서 아래(아군 진영)로.**
> 코드상으로는 `2x − y` 오름차순 → 동률이면 `y` 내림차순.
> (P1은 이 순서를 그대로 뒤집은 것)

24칸 전체 순번:

```
              (3,5)#03  (4,5)#08  (5,5)#13  (6,5)#18
         (2,4)#01  (3,4)#06  (4,4)#11  (5,4)#16  (6,4)#21
    (1,3)#00  (2,3)#04  (3,3)#09  (4,3)#14  (5,3)#19  (6,3)#23
         (1,2)#02  (2,2)#07  (3,2)#12  (4,2)#17  (5,2)#22
              (1,1)#05  (2,1)#10  (3,1)#15  (4,1)#20
```

| 세로축 | 순번 |
|---|---|
| 1 | `(1,3)`#00 |
| 2 | `(2,4)`#01 → `(1,2)`#02 |
| 3 | `(3,5)`#03 → `(2,3)`#04 → `(1,1)`#05 |
| 4 | `(3,4)`#06 → `(2,2)`#07 |
| 5 | `(4,5)`#08 → `(3,3)`#09 → `(2,1)`#10 |
| 6 | `(4,4)`#11 → `(3,2)`#12 |
| 7 | `(5,5)`#13 → `(4,3)`#14 → `(3,1)`#15 |
| 8 | `(5,4)`#16 → `(4,2)`#17 |
| 9 | `(6,5)`#18 → `(5,3)`#19 → `(4,1)`#20 |
| 10 | `(6,4)`#21 → `(5,2)`#22 |
| 11 | `(6,3)`#23 |

### 단일 패스 커서

`AttackCheck`는 `attack_index` 커서를 **한 방향으로만** 전진시킨다 (`GameLogic.cs:427-463`).

- 커서가 지나간 칸은 **다시 보지 않는다** → 그 자리에 유닛이 새로 생겨도 이번 전투에는 불참
- 아직 지나지 않은 칸은 커서가 도달할 때 평가된다 → **새로 생긴 유닛도 참여**
- 유닛이 공격을 마치고 `exhausted`가 되면 커서가 다음 칸으로 넘어간다
  (Fury 등으로 `exhausted`가 풀려 있으면 **같은 칸에서 재공격**)

**장소 카드는 공격하지 않는다** — `CanAttack()`이 `IsPlace()`면 false를 반환해 건너뛴다.
소환 멀미 개념은 없다. 새로 나온 유닛도 `exhausted`만 아니면 바로 공격한다.

## 3. 타겟 지정 우선순위

`AttackSearch` → `weapon.SearchTarget` 순으로 결정된다.

```
① 사거리 안 적 카드 수집 (GetAllEnemyTarget)
      ↓
② 장소(Place) 카드가 하나라도 있으면 → 장소만 후보
   없고 도발(Protection)이 있으면    → 도발만 후보
   둘 다 없으면                      → 전부 후보
      ↓  후보 중 무작위 1개
③ 후보가 있으면 → 유닛/장소 공격
   후보가 없으면 ↓
④ 사거리 안에 적 진영 **안쪽 칸**이 걸리면 → 플레이어 직접 공격
   아니면 ↓
⑤ 공격 불가 (ExhaustBattle, 그냥 넘어감)
```

**적 진영 안쪽 칸** (`Slot.GetInsideSlot`) — 진영의 바깥 테두리 6칸이다.

| 진영 | 안쪽 칸 |
|---|---|
| P0 | `(1,1) (2,1) (3,1) (4,1) (1,2) (5,2)` |
| P1 | `(3,5) (4,5) (5,5) (6,5) (2,4) (6,4)` |

> `Trinity_Vigilante_Crew` 클럽을 가진 유닛만 ③④ 순서가 뒤집힌다 —
> 직접 공격이 가능하면 유닛을 무시하고 플레이어를 친다.

## 4. 예시 필드

네 가지 타겟 지정 경우와 소환 유닛의 참여/불참을 한 전투에 모두 담은 배치다.

### 배치

```
              (3,5)     (4,5)     (5,5)     (6,5)
         [감시탑]   [보병]    (4,4)     (5,4)     (6,4)
    ▶A       (2,3)     (3,3)     (4,3)     ▶D       (6,3)
         ▶B       (2,2)     (3,2)     (4,2)     (5,2)
              ▶C       (2,1)     (3,1)     (4,1)
```

**아군 (P0)**

| 순번 | 슬롯 | 유닛 | 사거리 | 공격력 | 시연 |
|---|---|---|---|---|---|
| #00 | (1,3) | **A** 정찰병 | 2 | 2 | **장소 우선** |
| #02 | (1,2) | **B** 소총병 | 2 | 3 | **유닛 공격** |
| #05 | (1,1) | **C** 후방병 | 1 | 2 | **공격 불가** |
| #19 | (5,3) | **D** 돌격병 | 1 | 3 | **직접 공격** + 토큰 2기 소환 |

**적군 (P1)**

| 슬롯 | 카드 | 체력 | 공격력 |
|---|---|---|---|
| (2,4) | **감시탑** (장소) | 2 | — |
| (3,4) | **보병** | 5 | 1 |

### 사거리 계산

| 유닛 | 사거리 안 칸 | 적 카드 | 적 진영 안쪽 |
|---|---|---|---|
| A (1,3) r2 | (2,4)(1,2)(3,5)(2,3)(1,1)(3,4)(2,2)(3,3) | 감시탑, 보병 | (2,4)(3,5) |
| B (1,2) r2 | (1,3)(2,4)(2,3)(1,1)(3,4)(2,2)(3,3)(2,1)(3,2) | 감시탑, 보병 | (2,4) |
| C (1,1) r1 | (1,2)(2,2)(2,1) | **없음** | **없음** |
| D (5,3) r1 | (4,3)(5,4)(4,2)(6,4)(5,2)(6,3) | **없음** | (6,4) |

## 5. 전투 진행

| # | 커서 | 무슨 일 |
|---|---|---|
| 1 | **#00 A** | 사거리에 **감시탑(장소)** 과 보병이 둘 다 있다 → **장소 우선**으로 감시탑만 후보<br/>`OnBeforeAttack` → 데미지 2 → `OnAfterAttack`. 감시탑 체력 2 → 0 (빈사) |
| 2 | | A의 볼리 종료 → **사망 웨이브** → 감시탑 제거 |
| 3 | **#02 B** | 장소가 사라져 이제 보병이 후보 → **유닛 공격**<br/>`OnBeforeAttack`/`OnBeforeDefend` → 데미지 3 → 보병이 **반격 1** → `OnAfterAttack`/`OnAfterDefend` |
| 4 | **#05 C** | 사거리 3칸이 전부 아군 진영. 적 카드도, 적 진영 안쪽 칸도 없다 → **공격 불가**<br/>트리거 없이 `exhausted` 처리 후 통과 |
| 5 | **#19 D** | 사거리에 적 카드 없음. `(6,4)`가 적 진영 안쪽 → **플레이어 직접 공격**<br/>`OnAfterAttack`으로 토큰 2기 소환: **α → (4,2)#17**, **β → (6,3)#23** |
| 6 | #20~#22 | 빈 칸 통과. **α는 #17이라 커서가 이미 지나갔다 → 이번 전투 불참** |
| 7 | **#23 β** | 커서가 도달 → **참여**. 사거리 `(5,3)(6,4)(5,2)` 중 `(6,4)`가 적 진영 안쪽 → **직접 공격** |
| 8 | | 커서 끝 → 전투 종료 → `EndTurn` |

### 이 진행이 보여주는 것

**① 공격 순서** — A(#00) → B(#02) → C(#05) → D(#19) → β(#23).
세로축 1 → 2 → 3 → 9 → 11 순이고, 같은 세로축이면 위(적 진영)부터다.
D가 B보다 오른쪽(세로축 9)이라 한참 뒤에 온다 — **x가 크다고 늦은 게 아니라 세로축이 오른쪽이라 늦다.**

**② 타겟 지정 4경우** — 장소(A) → 유닛(B) → 직접 공격(D) → 공격 불가(C).
A와 B는 사거리 안에 **같은 두 카드**를 보고 있는데도 대상이 다르다. 장소 카드가 살아 있는
동안에는 무조건 장소가 우선이기 때문이다.

**③ 효과 순서** — `OnBeforeAttack` → 데미지(+반격) → `OnAfterAttack` → (볼리 종료) → 사망 웨이브.
공격에 죽은 카드는 **공격 후 트리거가 다 끝난 뒤에** 제거된다. 상세는
[`effect-resolution-flow.md`](effect-resolution-flow.md).

**④ 소환 위치가 참여를 가른다** — 같은 시점에 소환된 토큰인데도 α(#17)는 불참, β(#23)는 참여.
커서(#19)보다 **앞이냐 뒤냐**만으로 갈린다. 소환 멀미가 아니라 **순회 커서** 때문이다.

## 6. 볼리 (다중 대상)

한 유닛이 여러 대상을 때리는 경우 (`MassShooting` 등), 볼리 전체가 **하나의 논리적 Phase**다.

- 대상마다 `AttackTarget → ResolveAttack → ResolveAttackHit → ResolveDeath` 를 한 바퀴씩 돈다
- 그동안 죽음은 `death_step_suspended`로 **보류**된다
- 볼리가 끝나야 **한 웨이브**로 정리된다 → 다음 유닛은 항상 정리된 보드를 본다
- 이미 빈사인 대상은 다음 발에서 **건너뛴다** (overkill guard, `GameLogic.cs:1003`)

검증: `Tools/ResolveQueueTests/AttackTests.cs`의 `W06`~`W08`.
